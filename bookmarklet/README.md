# 쿠팡 반품 처리 데이터 수집 북마크릿

쿠팡 벤더/입점사 어드민의 반품(vendor-return) 목록 페이지에서 여러 행을 골라, 각 행의 상세 페이지 → 아이템 목록 → SKU별 재고(위치/수량) 정보를 자동으로 훑어서 엑셀에 바로 붙여넣을 수 있는 형태로 모아주는 브라우저 북마크릿입니다.

목록 페이지(`inbound.coupang.com`)와 재고조회 API(`inventory.coupang.com`)가 서로 다른 도메인이라 직접 `fetch()`하면 CORS로 막힙니다. 이 북마크릿은 **같은 북마크릿을 두 번 클릭**해서 이를 우회합니다:

1. 목록 페이지에서 클릭 → 데이터 수집 후, 재고조회 페이지(`inventory.coupang.com/inventory/list`)를 새 창으로 열고 그 창의 `window.name`에 수집한 데이터를 실어 보냄 (`window.name`은 탭이 다른 도메인으로 이동해도 유지되는 브라우저 특성 — CORS와 무관)
2. 새로 열린 재고조회 탭에서 **같은 북마크릿을 다시 클릭** → `window.name`에서 데이터를 읽고, 같은 출처(same-origin)로 재고 API를 호출 (CORS 문제 없음)

## 설치

1. `node bookmarklet/build.js` 실행
2. 콘솔에 출력되는 `javascript:...` 문자열을 복사 (또는 `bookmarklet/dist/bookmarklet.url.txt` 내용을 복사)
3. 브라우저에서 새 북마크를 만들고 URL 칸에 붙여넣기 (이름 예: "쿠팡 반품 스캔")

## 사용법

1. `#vendorReturnOrderPage`가 있는 목록 페이지로 이동해서 북마크릿 클릭
2. 팝업으로 뜨는 입력창에 처리할 행 번호 입력
   - 비워두면 전체 행
   - `4` → 4번 행만
   - `1,3,4` → 1, 3, 4번 행
   - `1-3` 또는 `1~3` → 1~3번 행
3. 수집이 끝나면 화면 우측 상단에 "N건 수집 완료, 새 탭에서 북마크릿을 한 번 더 눌러주세요"라는 알림이 잠깐 떴다 자동으로 사라지고, 재고조회 페이지가 새 창으로 열림 (예전처럼 클릭해서 닫아야 하는 alert 창이 아님)
4. **새로 열린 탭에서 같은 북마크릿을 다시 클릭** — 재고를 SKU별로 페이징하며 조회 (진행률 오버레이 표시)
5. 완료되면 새 창에 결과가 뜸 — 상단 "복사" 버튼을 누르면 바로 클립보드에 복사되고, 필요하면 "원본 데이터 (TSV) 보기"를 펼쳐 직접 복사할 수도 있음

## 결과 컬럼

그룹번호, 마감일자, 생성일자, 매입유형, 업체명, 상태, 운송타입, 존, 수량 (9개, 탭으로 구분됨). 존이 같은 그룹번호는 수량을 합산해서 한 줄로 모으고, 존 기준으로 정렬합니다.

## 동작 원리 요약

- 1단계에서 각 반품 건의 상세 페이지를 열어 그룹번호/마감일자/생성일자/매입유형/업체명/상태/운송타입을 읽고, 아이템 목록에서 **상태에 "집품"이 포함된 행만**(집품중/집품대기 등) skuId를 추출합니다.
- 2단계에서 각 skuId를 재고조회 API로 조회합니다. 이 API는 한 번에 최대 20건(`pageSize=20`)만 반환하므로, `page`를 늘려가며 `result.last === true`가 될 때까지 반복 조회합니다.
- 재고 항목 중 `locationType === "PICKING"`이고 수량(`allocatedQuantity`)이 1 이상인 것만 채택하고, `locationBarcode`(예: `149-72L105-16-301`)에서 두 번째 구간(`72L105`)이 숫자로 시작하면 앞 3글자(`72L`)를 존으로 사용합니다.

## 알려진 가정 / 리스크

- **집품 상태 필터**: 아이템 목록에서 상태값에 "집품"이 포함된 행만 채택합니다. 처리 결과가 예상보다 적으면 이 필터부터 의심하세요 — `bookmarklet/src/bookmarklet.js`의 `CONFIG.PICKING_STATUS_SUBSTR`를 조정하거나 `scrapeSkuIds` 함수의 필터 조건을 수정하면 됩니다.
- **상세 페이지 컬럼 위치**: table1/table2의 각 열 위치, 그리고 매입유형이 "쿠팡상품"인지 아닌지에 따라 마감일자 소스 위치가 달라지는 조건부 로직이 들어있습니다 — `scrapeCommonData` 함수 참고.
- **재고 API 페이지네이션**: `pageSize=20`이 현재 서버가 허용하는 최댓값이라는 전제입니다. 여전히 막히면 `CONFIG.INVENTORY_PAGE_SIZE`를 더 낮춰보세요.
- **재고 API 응답 구조**: `json.success`, `json.result.content`(배열), `json.result.last`(마지막 페이지 여부)를 전제로 합니다. 구조가 다르면 `fetchInventoryAllPages` 함수를 수정하세요.
- **window.name 특성**: 재고조회 탭을 닫거나 다른 곳으로 이동하면 데이터가 유실됩니다 — 이 경우 목록 페이지에서 1단계부터 다시 실행하세요.
- **팝업 차단**: 재고조회 탭을 자동으로 열 때와 결과 팝업 모두 팝업 차단에 걸릴 수 있습니다 — 두 사이트 모두 팝업을 허용해주세요.
- **처리 속도**: 각 요청 사이에 짧은 지연(`CONFIG.DELAY_MS`, 기본 120ms)을 두고 순차 처리합니다. 선택한 행/SKU가 많으면 시간이 걸릴 수 있습니다.

## 문제 발생 시 확인 방법 (검증 절차)

이 저장소 안에서는 실제 쿠팡 사이트에 접근할 수 없어 자동 테스트가 불가능합니다. 실제 환경에서 아래 순서로 확인하세요.

1. `node bookmarklet/build.js`가 에러 없이 실행되고 `javascript:` URI가 생성되는지 확인
2. 목록 페이지에서 콘솔을 열어둔 채로 북마크릿 실행 → 행 1개만 먼저 테스트
3. "데이터 수집 완료" 알림이 뜨고 새 탭이 열리는지 확인. 안 뜨면 콘솔에서 어느 링크 처리 중 실패했는지(`링크 처리 실패:` 로그) 확인
4. 새 탭에서 콘솔을 열어둔 채로 북마크릿 재실행 → 진행률 오버레이와 함께 여러 `page` 요청이 순차적으로 나가는지 확인
5. "수집된 데이터가 없습니다" 알림이 뜨면: 집품 상태 필터에 걸리는지, 혹은 재고 API 응답 구조가 예상과 다른지(`skuId=... 재고 조회 실패:` 콘솔 로그) 확인
6. 결과 팝업의 헤더가 9개 컬럼과 맞는지, 2~3건 정도 원본 페이지와 대조해서 값이 맞는지 확인
7. 엑셀/구글시트에 붙여넣어 컬럼이 깨지지 않는지 확인
8. 컬럼 값이 뒤섞여 보이면 `CONFIG`나 `scrapeCommonData`/`scrapeSkuIds`의 인덱스/조건을 조정하고 `node bookmarklet/build.js`로 재빌드
