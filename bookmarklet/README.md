# 쿠팡 반품 처리 데이터 수집 북마크릿

쿠팡 벤더/입점사 어드민의 반품(vendor-return) 목록 페이지에서 여러 행을 골라, 각 행의 상세 페이지 → 아이템 목록 → SKU별 재고(위치/수량) 정보를 자동으로 훑어서 엑셀에 바로 붙여넣을 수 있는 형태로 모아주는 브라우저 북마크릿입니다.

목록 페이지(`inbound.coupang.com`)와 재고조회 API(`inventory.coupang.com`)가 서로 다른 도메인이라, 브라우저가 크로스 오리진 요청을 CORS로 차단합니다. 이를 우회하기 위해 북마크릿을 **2개**로 나눴습니다: 목록 페이지에서 실행하는 **메인 북마크릿**과, 재고조회 페이지에서 실행하는 **릴레이 북마크릿**. 릴레이가 같은 출처(same-origin)에서 대신 fetch를 수행하고, 그 결과를 `postMessage`로 메인 북마크릿에 전달합니다.

## 설치

1. `node bookmarklet/build.js` 실행
2. 콘솔에 출력되는 두 개의 `javascript:...` URI를 확인 (또는 `bookmarklet/dist/bookmarklet.url.txt`, `bookmarklet/dist/relay.url.txt` 파일 내용을 각각 복사)
3. 브라우저 북마크 2개를 만들기:
   - 이름 예: "쿠팡 반품 스캔" → URL에 `bookmarklet.url.txt` 내용 붙여넣기
   - 이름 예: "재고조회 릴레이" → URL에 `relay.url.txt` 내용 붙여넣기

## 사용법

1. **먼저** `https://inventory.coupang.com/inventory/list` 탭을 열고 **"재고조회 릴레이"** 북마크릿 클릭
   - "릴레이 준비 완료" 알림이 뜨면 성공. 이 탭은 작업 끝날 때까지 닫지 말 것 (새로고침도 금지 — 새로고침하면 릴레이가 사라짐)
2. `#vendorReturnOrderPage` 테이블이 있는 목록 페이지로 이동해서 **"쿠팡 반품 스캔"** 북마크릿 클릭
3. 팝업으로 뜨는 입력창에 처리할 행 번호 입력
   - 비워두면 전체 행
   - `4` → 4번 행만
   - `1,3,4` → 1, 3, 4번 행
   - `1-3` 또는 `1~3` → 1~3번 행
4. 처리가 끝나면 새 창에 결과가 뜸 — 텍스트 영역이 자동 선택되어 있으니 바로 `Ctrl+C` 하거나 "복사" 버튼 클릭 후 엑셀에 붙여넣기

만약 "재고조회 릴레이가 준비되지 않았습니다" 알림이 뜨면: 1번으로 돌아가 릴레이 탭에서 릴레이 북마크릿을 다시 클릭한 뒤, 메인 북마크릿을 다시 실행하세요.

## 결과 컬럼

그룹번호, 마감일시, 생성일시, 매입유형, 업체명, 상태, 운송타입, 존, 수량 (9개, 탭으로 구분됨)

## 알려진 가정 / 리스크

이 코드는 실제 쿠팡 사이트에 접근하지 않고 명세만으로 작성되었기 때문에, 아래 항목들은 실제 페이지와 다를 수 있습니다. 문제가 생기면 `bookmarklet/src/bookmarklet.js` 최상단의 `CONFIG` 객체만 수정하면 됩니다.

- **테이블 id**: `#vendorReturnOrderPage`
- **상세 페이지 컬럼 인덱스**: 상세 페이지에 테이블이 최소 2개 있다고 가정하고, 첫 번째/두 번째 테이블의 특정 열(`CONFIG.DETAIL_TABLE1_COLS`, `CONFIG.DETAIL_TABLE2_COLS`)을 읽습니다. 실제와 다르면 이 값들을 수정하세요.
- **재고 API(JSON) 응답 구조**: 응답이 배열 자체이거나 `.content`/`.data`/`.list`/`.rows` 중 하나일 것으로 가정합니다(`CONFIG.INVENTORY_ARRAY_PATHS`). 맞는 경로가 없으면 콘솔에 `"알 수 없는 재고 API 응답 구조, 원본 JSON: ..."` 로그가 찍히니, 실제 구조를 확인해서 `INVENTORY_ARRAY_PATHS`에 경로를 추가하세요.
- **릴레이 탭 유지 필요**: `inventory.coupang.com` 탭을 닫거나 새로고침하면 릴레이가 사라집니다. 이 경우 메인 북마크릿 실행 시 "재고조회 릴레이가 준비되지 않았습니다" 알림이 뜹니다 — 릴레이 북마크릿을 다시 실행하면 됩니다.
- **팝업 차단**: 릴레이 탭을 자동으로 열 때(`window.open`)와 결과 팝업 모두 팝업 차단에 걸릴 수 있습니다 — 두 사이트 모두 팝업을 허용해주세요.
- **postMessage 보안**: 메인 ↔ 릴레이 통신은 정해진 origin(`https://inventory.coupang.com`)으로만 주고받고, 메시지의 `source` 식별자를 검증해서 다른 탭/스크립트의 메시지가 섞이지 않도록 합니다.
- **클립보드 복사**: `navigator.clipboard.writeText`가 실패하는 환경에서도 텍스트 영역이 자동 선택되어 있으니 `Ctrl+C`로 수동 복사할 수 있습니다.
- **처리 속도**: 각 요청 사이에 짧은 지연(`CONFIG.DELAY_MS`, 기본 150ms)을 두고 순차적으로 처리합니다. 선택한 행/SKU가 많으면 시간이 걸릴 수 있습니다(서버 부하 방지 및 안정성 우선). 재고 조회는 SKU 하나당 최대 `REQUEST_TIMEOUT_MS`(기본 10초)까지 기다리며, 타임아웃되면 그 SKU만 건너뛰고 나머지는 계속 진행합니다.

## 문제 발생 시 확인 방법 (검증 절차)

이 저장소 안에서는 실제 쿠팡 사이트에 접근할 수 없어 자동 테스트가 불가능합니다. 실제 환경에서 아래 순서로 확인하세요.

1. `node bookmarklet/build.js`가 에러 없이 실행되고 두 `javascript:` URI가 모두 생성되는지 확인
2. `inventory.coupang.com/inventory/list` 탭을 열고 콘솔을 띄운 채로 릴레이 북마크릿 실행 → "릴레이가 준비되었습니다" 로그와 알림 확인
3. 목록 페이지에서 콘솔을 열어둔 채로 메인 북마크릿 실행 → 행 1개만 먼저 테스트
4. 콘솔에 뜨는 경고/에러 확인:
   - 테이블/링크를 못 찾는다는 경고 → 페이지 구조가 예상과 다름 → `CONFIG`의 id나 컬럼 인덱스 확인
   - "재고조회 릴레이가 준비되지 않았습니다" alert → 릴레이 탭이 닫혔거나 릴레이를 실행 안 한 것 — 2번부터 다시
   - "알 수 없는 재고 API 응답 구조" → JSON 구조 확인 후 `INVENTORY_ARRAY_PATHS`에 경로 추가
   - "릴레이 응답 없음 (타임아웃)" → 릴레이 탭이 응답하지 못함 (탭이 백그라운드로 오래 방치되어 스로틀링됐거나 네트워크 지연) — 재시도
5. 결과 팝업의 헤더가 9개 컬럼과 맞는지, 2~3건 정도 원본 페이지와 대조해서 값이 맞는지 확인
6. 엑셀/구글시트에 붙여넣어 컬럼이 깨지지 않는지 확인
7. 컬럼 값이 뒤섞여 보이면(예: 상태 자리에 날짜가 나옴) `CONFIG.DETAIL_TABLE1_COLS` / `DETAIL_TABLE2_COLS`의 인덱스를 조정하고 `node bookmarklet/build.js`로 재빌드
