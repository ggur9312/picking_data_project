# 쿠팡 반품 처리 데이터 수집 북마크릿

쿠팡 벤더/입점사 어드민의 반품(vendor-return) 목록 페이지에서 여러 행을 골라, 각 행의 상세 페이지 → 아이템 목록 → SKU별 재고(위치/수량) 정보를 자동으로 훑어서 엑셀에 바로 붙여넣을 수 있는 형태로 모아주는 브라우저 북마크릿입니다.

목록 페이지(`inbound.coupang.com`)와 재고조회 API(`inventory.coupang.com`)가 서로 다른 도메인이라 직접 `fetch()`하면 CORS로 막힙니다. 이 북마크릿은 **같은 북마크릿을 두 번 클릭**해서 이를 우회합니다:

1. 목록 페이지에서 클릭 → 데이터 수집 후, 재고조회 페이지(`inventory.coupang.com/inventory/list`)를 새 창으로 열고 그 창의 `window.name`에 수집한 데이터를 실어 보냄 (`window.name`은 탭이 다른 도메인으로 이동해도 유지되는 브라우저 특성 — CORS와 무관)
2. 새로 열린 재고조회 탭에서 **같은 북마크릿을 다시 클릭** → `window.name`에서 데이터를 읽고, 같은 출처(same-origin)로 재고 API를 호출 (CORS 문제 없음)

## 설치

Node.js 설치 없이 브라우저만으로 설치할 수 있습니다 (`bookmarklet/builder.html` 이용):

1. `bookmarklet/builder.html` 파일을 다운로드해서 더블클릭(또는 브라우저에 드래그)으로 열기 — 인터넷 연결이나 서버, Node 설치 전혀 필요 없음
2. `bookmarklet/src/bookmarklet.js`의 전체 내용을 복사해서 "원본 JS 코드" 칸에 붙여넣기
3. "생성하기" 클릭
4. 나온 "🔖 이 링크를 북마크바로 드래그하세요" 링크를 브라우저 북마크바로 드래그 (또는 아래 텍스트를 복사해서 새 북마크의 URL 칸에 붙여넣기)

(참고: 저장소에는 Node.js로 미리 빌드해둔 `bookmarklet/dist/bookmarklet.url.txt`도 커밋되어 있으니, 코드를 직접 수정할 게 아니라면 이 파일 내용을 그대로 복사해 써도 됩니다.)

## 사용법

1. `#vendorReturnOrderPage`가 있는 목록 페이지로 이동해서 북마크릿 클릭
2. 페이지 안에 **수집 모달**이 뜸. 여기서 두 가지를 고름:
   - **수집 범위**
     - `현재 페이지만` (기본) — 화면에 보이는 행만 처리 (기존 동작)
     - `전체 페이지` — 지금 걸려 있는 검색 조건 그대로 모든 페이지를 서버에서 가져와 처리
   - **처리할 행 번호**
     - 비워두면 전체 행
     - `4` → 4번 행만
     - `1,3,4` → 1, 3, 4번 행
     - `1-3` 또는 `1~3` → 1~3번 행
     - `전체 페이지` 모드에서는 행 번호가 **모든 페이지를 이어 붙인 순서**(1페이지 1행 = 1번)를 가리킴
3. 수집이 끝나면 화면 우측 상단에 "N건 수집 완료, 새 탭에서 북마크릿을 한 번 더 눌러주세요"라는 알림이 잠깐 떴다 자동으로 사라지고, 재고조회 페이지가 새 창으로 열림
4. **새로 열린 탭에서 같은 북마크릿을 다시 클릭** — 재고를 SKU별로 페이징하며 조회 (진행률 표시)
   - 조회가 오래 걸리면 진행률 모달의 **`취소` 버튼(또는 `Esc`)으로 언제든 중단**할 수 있습니다. 진행 중이던 요청도 즉시 끊깁니다. 1단계 수집 중에도 마찬가지입니다.
   - 취소하면 **그때까지 모은 데이터는 버립니다.** 다만 2단계에서 취소한 경우에는 1단계 수집 결과를 되돌려 놓으므로, 같은 탭에서 북마크릿만 다시 누르면 처음부터 다시 조회할 수 있습니다 (1단계부터 할 필요 없음).
5. 완료되면 **같은 페이지 안에 결과 모달**이 뜸 — "복사" 버튼을 누르면 바로 클립보드에 복사되고, 필요하면 "원본 데이터 (TSV) 보기"를 펼쳐 직접 복사할 수도 있음

> 알림·입력·결과 UI는 전부 현재 페이지 안에 그려지는 모달입니다. 예전처럼 결과를 별도 창(`window.open`)으로 띄우지 않기 때문에, **다른 탭을 닫아도 결과 모달의 복사/닫기 버튼이 먹통이 되지 않습니다.** (닫기: 버튼 / 배경 클릭 / `Esc`)

## 결과 컬럼

그룹번호, 마감일시, 생성일시, 매입유형, 업체명, 상태, 운송타입, 존, 수량 (9개, 탭으로 구분됨). 마감/생성 값은 원본에서 시간을 떼고 날짜만 남깁니다. 존이 같은 그룹번호는 수량을 합산해서 한 줄로 모으고, 존 기준으로 정렬합니다.

## 동작 원리 요약

- `전체 페이지` 모드에서는 목록 페이징 API(`/vendor-return/order/paging`)를 직접 호출합니다. 목록 페이지와 같은 출처라 CORS 문제가 없습니다. 검색 조건은 하드코딩하지 않고 **페이지의 검색 폼에서 현재 값을 읽어** 그대로 실어 보냅니다(`isVirtualVendorReturn`, `vendorReturnWorkId`, `skuExternalId`, `skuBarcode`, `vendorName`, `vendorReturnOrderExternalId`, `vendorReturnOrderId`, `agent`, `status`, `start`, `end`).
- 이때 `size=10000`으로 한 번에 요청하되, 서버가 이 값을 무시하고 더 작게 잘라서 주더라도 **새 링크가 하나도 없는 페이지가 나올 때까지** `page`를 늘려가며 계속 요청하므로 두 경우 모두 전량을 가져옵니다 (최대 200페이지).
- 1단계에서 각 반품 건의 상세 페이지를 열어 그룹번호/마감일시/생성일시/매입유형/업체명/상태/운송타입을 읽고, 아이템 목록에서 **상태에 "집품"이 포함된 행만**(집품중/집품대기 등) skuId를 추출합니다.
- 2단계에서 각 skuId를 재고조회 API로 조회합니다. 이 API는 한 번에 최대 20건(`pageSize=20`)만 반환하므로, `page`를 늘려가며 `result.last === true`가 될 때까지 반복 조회합니다.
- 재고 항목 중 `locationType === "PICKING"`이고 수량(`allocatedQuantity`)이 1 이상인 것만 채택하고, `locationBarcode`(예: `149-72L105-16-301`)에서 두 번째 구간(`72L105`)이 숫자로 시작하면 앞 3글자(`72L`)를 존으로 사용합니다.

## 알려진 가정 / 리스크

- **집품 상태 필터**: 아이템 목록에서 상태값에 "집품"이 포함된 행만 채택합니다. 처리 결과가 예상보다 적으면 이 필터부터 의심하세요 — `bookmarklet/src/bookmarklet.js`의 `CONFIG.PICKING_STATUS_SUBSTR`를 조정하거나 `scrapeSkuIds` 함수의 필터 조건을 수정하면 됩니다.
- **상세 페이지 컬럼 위치**: table1/table2의 각 열 위치, 그리고 매입유형이 "쿠팡상품"인지 아닌지에 따라 마감일시 소스 위치가 달라지는 조건부 로직이 들어있습니다 — `scrapeCommonData` 함수 참고.
- **재고 API 페이지네이션**: `pageSize=20`이 현재 서버가 허용하는 최댓값이라는 전제입니다. 여전히 막히면 `CONFIG.INVENTORY_PAGE_SIZE`를 더 낮춰보세요.
- **재고 API 응답 구조**: `json.success`, `json.result.content`(배열), `json.result.last`(마지막 페이지 여부)를 전제로 합니다. 구조가 다르면 `fetchInventoryAllPages` 함수를 수정하세요.
- **검색 폼 필드 이름**: `전체 페이지` 모드는 검색 조건을 `input`/`select`의 `name` 속성으로 찾습니다. 어드민 UI가 개편되어 `name`이 바뀌면 조건이 빈 값으로 나가 결과가 이상해질 수 있습니다 — 콘솔에 찍히는 `[북마크릿] 목록 전체 조회 파라미터:` 로그를 실제 요청과 대조하고, `CONFIG.LIST_PARAM_NAMES`를 고치세요.
- **window.name 특성**: 재고조회 탭을 닫거나 다른 곳으로 이동하면 데이터가 유실됩니다 — 이 경우 목록 페이지에서 1단계부터 다시 실행하세요. 수집량이 아주 많으면(`CONFIG.MAX_PAYLOAD_CHARS` 초과) 전달 실패 가능성을 경고 모달로 알립니다.
- **팝업 차단**: 결과는 이제 모달이라 팝업 차단과 무관하지만, 1단계에서 재고조회 탭을 자동으로 열 때는 여전히 팝업 허용이 필요합니다.
- **세션 만료**: 조회 도중 로그인이 풀리면(로그인 페이지로 리다이렉트 / 401 / 403 / 응답 본문이 로그인 화면) **즉시 전체를 중단**하고 안내 모달을 띄웁니다. 그때까지 모은 데이터는 버립니다. 2단계에서 만료된 경우에는 1단계 수집 결과를 `window.name`에 되돌려 놓으므로, 다시 로그인한 뒤 같은 탭에서 북마크릿만 누르면 됩니다. 판별은 경로 이름(`/login` 등)이 아니라 **리다이렉트 여부 + 최종 경로가 요청 경로와 다른지**로 하므로 어드민 구조가 바뀌어도 동작하고, 슬래시 정규화 같은 동일 경로 리다이렉트에는 반응하지 않습니다.
- **호스트 페이지 CSS 격리**: 모달은 Shadow DOM(`#cpm-ui-root`) 안에서 렌더되므로 어드민 페이지의 CSS가 `!important`를 쓰더라도 선택자로 침투하지 못합니다. 상속되는 속성은 `:host{all:initial}`로 끊습니다. `attachShadow`를 지원하지 않는 아주 오래된 브라우저에서는 격리 없이 동작하며, 이 경우에만 스타일 침투 가능성이 남습니다.
- **호스트 페이지 배율**: 어드민이 조상 요소에 `zoom`이나 `transform:scale`을 걸어두면 모달도 같이 확대/축소됩니다 (Shadow DOM은 스타일 침투만 막을 뿐 이런 레이아웃 배율은 통과시킵니다). 그래서 모달을 `body`가 아니라 `documentElement`(`<html>`)에 붙이고, 그래도 남는 배율은 알려진 높이의 프로브를 실제로 그려 재서 역배율로 상쇄합니다. 페이지마다 글씨 크기가 달라 보이면 콘솔의 `[북마크릿] 호스트 배율:` 로그를 확인하세요 (보정이 걸리지 않았다면 로그가 없습니다).
- **처리 속도**: 각 요청 사이에 짧은 지연(`CONFIG.DELAY_MS`, 기본 120ms)을 두고 순차 처리합니다. 선택한 행/SKU가 많으면 시간이 걸릴 수 있습니다.

## 문제 발생 시 확인 방법 (검증 절차)

이 저장소 안에서는 실제 쿠팡 사이트에 접근할 수 없어 자동 테스트가 불가능합니다. 실제 환경에서 아래 순서로 확인하세요.

1. `bookmarklet/builder.html`을 열어 소스를 붙여넣고 "생성하기"를 눌렀을 때 에러 없이 `javascript:` 링크가 나오는지 확인 (또는 Node이 있다면 `node bookmarklet/build.js`)
2. 목록 페이지에서 콘솔을 열어둔 채로 북마크릿 실행 → `현재 페이지만` + 행 1개로 먼저 테스트
3. "N건 수집 완료" 토스트가 뜨고 새 탭이 열리는지 확인. 안 뜨면 콘솔에서 어느 링크 처리 중 실패했는지(`링크 처리 실패:` 로그) 확인
4. 새 탭에서 콘솔을 열어둔 채로 북마크릿 재실행 → 진행률 표시와 함께 여러 `page` 요청이 순차적으로 나가는지 확인
   - 이때 `취소`를 눌러 즉시 멈추는지, Network 탭에서 추가 요청이 끊기는지, 이어서 북마크릿을 다시 눌렀을 때 정상 동작하는지도 함께 확인
5. 조회 도중 다른 탭에서 로그아웃 → 수집이 **바로 멈추고** 로그인 안내 모달이 뜨는지, Network 탭에서 그 시점 이후 요청이 끊겼는지 확인. 2단계였다면 다시 로그인 후 같은 탭에서 북마크릿만 눌러 이어지는지도 확인
6. "수집된 데이터가 없습니다" 알림이 뜨면: 집품 상태 필터에 걸리는지, 혹은 재고 API 응답 구조가 예상과 다른지(`skuId=... 재고 조회 실패:` 콘솔 로그) 확인
7. 결과 모달의 헤더가 9개 컬럼과 맞는지, 2~3건 정도 원본 페이지와 대조해서 값이 맞는지 확인
8. **결과 모달이 뜬 상태에서 원래 목록 페이지 탭을 닫고**, 복사/닫기 버튼이 그대로 동작하는지 확인 (예전 별도 창 방식에서 먹통이 되던 부분)
9. 엑셀/구글시트에 붙여넣어 컬럼이 깨지지 않는지 확인
10. `전체 페이지` 모드 확인: Network 탭을 열고 실행 → `/vendor-return/order/paging` 요청에 **지금 걸어둔 검색 조건이 그대로 실려 있는지**, 수집 건수가 목록 화면의 전체 건수와 맞는지 대조
11. 컬럼 값이 뒤섞여 보이면 `CONFIG`나 `scrapeCommonData`/`scrapeSkuIds`의 인덱스/조건을 조정하고 `bookmarklet/builder.html`(또는 `node bookmarklet/build.js`)로 재빌드
