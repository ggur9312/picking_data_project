# 쿠팡 반품 처리 데이터 수집 북마크릿

쿠팡 벤더/입점사 어드민의 반품(vendor-return) 목록 페이지에서 여러 행을 골라, 각 행의 상세 페이지 → 아이템 목록 → SKU별 재고(위치/수량) 정보를 자동으로 훑어서 엑셀에 바로 붙여넣을 수 있는 형태로 모아주는 브라우저 북마크릿입니다.

## 설치

1. `node bookmarklet/build.js` 실행
2. 콘솔에 출력되는 `javascript:...` 로 시작하는 긴 문자열을 복사 (또는 `bookmarklet/dist/bookmarklet.url.txt` 파일 내용을 복사)
3. 브라우저에서 새 북마크를 만들고, 이름은 원하는 대로(예: "쿠팡 반품 스캔"), URL 칸에 복사한 `javascript:...` 문자열을 그대로 붙여넣기

## 사용법

1. `#vendorReturnOrderPage` 테이블이 있는 목록 페이지로 이동
2. 방금 만든 북마크릿 클릭
3. 팝업으로 뜨는 입력창에 처리할 행 번호 입력
   - 비워두면 전체 행
   - `4` → 4번 행만
   - `1,3,4` → 1, 3, 4번 행
   - `1-3` 또는 `1~3` → 1~3번 행
4. 처리가 끝나면 새 창에 결과가 뜸 — 텍스트 영역이 자동 선택되어 있으니 바로 `Ctrl+C` 하거나 "복사" 버튼 클릭 후 엑셀에 붙여넣기

## 결과 컬럼

그룹번호, 마감일시, 생성일시, 매입유형, 업체명, 상태, 운송타입, 존, 수량 (9개, 탭으로 구분됨)

## 알려진 가정 / 리스크

이 코드는 실제 쿠팡 사이트에 접근하지 않고 명세만으로 작성되었기 때문에, 아래 항목들은 실제 페이지와 다를 수 있습니다. 문제가 생기면 `bookmarklet/src/bookmarklet.js` 최상단의 `CONFIG` 객체만 수정하면 됩니다.

- **테이블 id**: `#vendorReturnOrderPage`
- **상세 페이지 컬럼 인덱스**: 상세 페이지에 테이블이 최소 2개 있다고 가정하고, 첫 번째/두 번째 테이블의 특정 열(`CONFIG.DETAIL_TABLE1_COLS`, `CONFIG.DETAIL_TABLE2_COLS`)을 읽습니다. 실제와 다르면 이 값들을 수정하세요.
- **재고 API(JSON) 응답 구조**: 응답이 배열 자체이거나 `.content`/`.data`/`.list`/`.rows` 중 하나일 것으로 가정합니다(`CONFIG.INVENTORY_ARRAY_PATHS`). 맞는 경로가 없으면 콘솔에 `"알 수 없는 재고 API 응답 구조, 원본 JSON: ..."` 로그가 찍히니, 실제 구조를 확인해서 `INVENTORY_ARRAY_PATHS`에 경로를 추가하세요.
- **크로스 도메인 요청**: 목록 페이지가 속한 도메인과 `inbound.coupang.com`, `inventory.coupang.com`으로의 `fetch` 요청은 `credentials: 'include'`로 쿠키를 포함해 보냅니다. 만약 이 도메인들 간 CORS 정책이 크로스 오리진 인증 요청을 막고 있다면, 콘솔에 CORS 관련 에러(`Failed to fetch` 등)가 즉시 나타납니다 — 이는 북마크릿 코드로는 우회할 수 없는 서버 측 정책이므로, 발생 시 별도 방법(같은 오리진에서 실행되는 확장 프로그램 등)을 검토해야 합니다.
- **팝업 차단**: 브라우저가 팝업을 차단하면 결과 창이 뜨지 않습니다 — 사이트에 대해 팝업을 허용해주세요.
- **클립보드 복사**: `navigator.clipboard.writeText`가 실패하는 환경에서도 텍스트 영역이 자동 선택되어 있으니 `Ctrl+C`로 수동 복사할 수 있습니다.
- **처리 속도**: 각 요청 사이에 짧은 지연(`CONFIG.DELAY_MS`, 기본 150ms)을 두고 순차적으로 처리합니다. 선택한 행/SKU가 많으면 시간이 걸릴 수 있습니다(서버 부하 방지 및 안정성 우선).

## 문제 발생 시 확인 방법 (검증 절차)

이 저장소 안에서는 실제 쿠팡 사이트에 접근할 수 없어 자동 테스트가 불가능합니다. 실제 환경에서 아래 순서로 확인하세요.

1. `node bookmarklet/build.js`가 에러 없이 실행되고 `javascript:` URI가 생성되는지 확인
2. 목록 페이지에서 개발자도구 콘솔을 열어둔 채로 북마크릿 실행
3. 먼저 행 1개만 입력해서 빠르게 동작을 확인 (전체 행은 그다음에)
4. 콘솔에 뜨는 경고/에러 확인:
   - 테이블/링크를 못 찾는다는 경고 → 페이지 구조가 예상과 다름 → `CONFIG`의 id나 컬럼 인덱스 확인
   - "알 수 없는 재고 API 응답 구조" → JSON 구조 확인 후 `INVENTORY_ARRAY_PATHS`에 경로 추가
   - CORS/네트워크 에러 → 위 "크로스 도메인 요청" 항목 참고
5. 결과 팝업의 헤더가 9개 컬럼과 맞는지, 2~3건 정도 원본 페이지와 대조해서 값이 맞는지 확인
6. 엑셀/구글시트에 붙여넣어 컬럼이 깨지지 않는지 확인
7. 컬럼 값이 뒤섞여 보이면(예: 상태 자리에 날짜가 나옴) `CONFIG.DETAIL_TABLE1_COLS` / `DETAIL_TABLE2_COLS`의 인덱스를 조정하고 `node bookmarklet/build.js`로 재빌드
